## 1. 프로젝트 코드 및 시뮬레이션 모델의 권리 범위

* **자체 제작 소스코드:** `breadboard/index.html` 내 논리 시뮬레이션 엔진, RC 아날로그 근사 풀이, UI/렌더링 코드, 기본 예제 회로(`EXAMPLES`)는 교육 및 실험 목적을 위해 자체 설계·구현되었습니다.
* **기능적 사양과 표현의 분리:** 74HC/74LS 시리즈, CD4511, NE555 등 범용 집적회로(IC)의 핀 번호, 입출력 논리 테이블, 기본 동작 특성은 호환성과 표준 규격에 기반한 **기능적·사실적 정보**를 바탕으로 구현되었으며, 특정 반도체 제조사의 공식 데이터시트 도면·문구·레이아웃을 그대로 복제하지 않습니다.
* **반도체 배치설계권 비침해:** 본 시뮬레이터는 핀 단위의 논리적·전기적 동작만을 모사하며, 실제 IC칩 내부의 트랜지스터·배선 배치설계(Mask Work)나 상용 펌웨어·마이크로코드를 추출·복제·배포하지 않습니다.

## 2. 상표 및 표준 형번 표기 원칙

* 본 프로젝트에서 사용하는 `74LS00`, `74HC00`, `NE555`, `CD4511` 등의 명칭은 전자공학 및 교육 현장에서 통용되는 범용 부품 번호(Generic Part Numbers)를 지칭합니다.
* 각 반도체 제조사가 보유한 등록 상표 및 로고는 해당 권리자에게 귀속되며, 본 프로젝트는 특정 제조사의 공식 제품이거나 제휴·보증된 소프트웨어가 아닙니다.
* 향후 신규 부품(`CHIPS`, `GATES`)을 추가할 때는 특정 기업의 고유 브랜드명이나 상표를 제품명처럼 사용하지 않고, 표준 기능명 또는 범용 형번 위주로 표기합니다.

## 3. 외부 리소스 및 오픈소스 라이선스 관리

* **웹 폰트:** 외부 웹폰트를 불러오지 않습니다(2026-11-26 Google Fonts 연결 제거). 글꼴은 사용자 기기에 깔린 시스템 기본 글꼴(`system-ui`, 맑은 고딕, Apple SD Gothic Neo, Consolas 등)만 CSS 이름으로 지정하며, 글꼴 파일을 포함·배포하지 않습니다. 새 글꼴을 넣을 때는 SIL OFL 1.1처럼 웹 임베딩·상업 이용이 허용된 것만 쓰고 7절 표에 기록합니다.
* **GPL·AGPL 코드 혼입 금지:** 카피레프트(GPL·AGPL) 코드는 한 줄도 복사하거나 참고해 넣지 않습니다. MIT·BSD·Apache 2.0 코드를 참고·포함하면 이 문서와 `index.html` 맨 위 주석에 원저작자·연도·라이선스 전문을 적습니다(현재 해당 없음).
* **자체 구현 원칙:** 아래 기능은 공개 표준 명세만 보고 직접 작성했습니다. 다른 프로젝트의 코드를 옮기지 않았습니다.

  | 기능 | 함수 | 참고한 것(규격·일반 알고리즘) |
  |---|---|---|
  | ZIP 묶기 | `makeZip`, `crc32` | ZIP 파일 형식(저장 방식, 압축 없음), CRC-32 표준 다항식 0xEDB88320 |
  | PCB 자동 배선 | `pcbAutoRoute`, `routeOnce` | 격자 위 A* 길 찾기(교과서 알고리즘), 방향·층 상태, 비아 비용 |

## 8. 점검 기록

* **2026-11-26 (20차 부품: 아날로그 IC·금속 캔·모듈 블록)** — 사용자가 붙여 넣은 계측기(스펙트럼 분석기) 부품 명세 문서를 14절 기준으로 반영. 문서는 저장소에 넣지 않고 핀 번호·정격 같은 사실만 써서 부품 설명을 직접 씀. 같은 날 사용자가 원본 명세(「HP 8566B 기반 CAD 부품 라이브러리」)를 다시 붙여 넣어, 부품 이름·정격·핀을 그 문서의 사실에 맞춰 고침(이미 있던 부품은 새로 만들지 않고 중립 ID만 붙임 — 600V 1A 브리지 → 기존 `brdg`, 6채널 D 플립플롭 → 기존 74LS174). 이름은 표준 등록 번호(74LS174)와 기능 이름("듀얼 JFET 입력 연산 증폭기", "가변 양전압 레귤레이터", "10비트 곱셈형 D/A 변환기", "16/32비트 마이크로프로세서", "YIG 동조 발진기")만 쓰고, 회사 전용 형번·계측기 회사 이름은 쓰지 않음. 부품마다 문서의 중립 ID(`nid`, 예: `OPAMP_DUAL_JFET_25VUS`)를 달아 목록 불러오기에 씀. TO-3·TO-18·TO-39·TO-99는 표준 패키지 외형 이름, 그림·발자국·예제 Ⓟ8은 자체 코드. 외부 에셋 없음.

TO-92·TO-220은 표준 패키지 외형 이름. 그림(TO-92 반원·TO-220 방열판)과 회로도 기호는 자체 SVG 코드. 외부 자료·에셋 없음.

## 13. 라이선스 키 (기술적 보호조치, 2026-11-26 추가)

* **목적:** 파일을 그대로 복사해 다른 사이트나 내 컴퓨터(file://)에서 쓰는 것을 막는다. 공식 주소(`co2maker-cyber.github.io`, Claude 미리보기)에서는 키 없이 쓴다. 그 밖에서 열면 **라이선스 키 창**이 화면을 막고, 저작자가 발급한 키를 넣어야 쓸 수 있다.
* **방식:** ECDSA P-256 전자서명. 프로그램(`index.html`의 `LIC_PUB`)에는 **공개 열쇠**만 있고, 키는 저작자의 **비밀 열쇠**로만 만들 수 있다. 키 = `BBCAD1.` + 내용(받는 사람·쓸 수 있는 곳·만료일·키 번호) + 서명. 내용을 한 글자라도 고치면 서명이 맞지 않아 거절된다.
* **쓸 수 있는 곳(`dom`):** `file`(내 컴퓨터에서 연 파일), `example.com`, `.example.com`(하위 도메인 포함), `*`(어디서나).
* **발급:** `breadboard/license-admin.html`(브라우저, 비밀 열쇠 파일을 열어서) 또는 `node breadboard/tools/issue-license.js --key 비밀열쇠.jwk.json --to "이름" --dom file --exp 2027-12-31`.
* **개인용 로컬 버전:** 발급 페이지의 [로컬 버전 파일 만들기] 또는 `issue-license.js … --dom file --build 파일.html`로, 받는 사람의 키를 `LIC_EMBED` 줄에 미리 넣은 파일을 만든다. 받은 사람은 더블클릭으로 인터넷 없이 쓴다. 파일 안 주석·제목·[속성] 안내에 받는 사람 이름과 키 번호가 남아, 퍼뜨리면 출처가 드러난다(파일 이름은 `breadboard-CAD-local-키번호.html`).
* **취소:** 키 번호(`L-…`)를 `index.html`의 `LIC_REVOKED`에 넣고 새로 배포한다.
* **비밀 열쇠 보관:** 저장소에 절대 넣지 않는다(`.gitignore`: `*PRIVATE*.jwk.json`). 잃어버리면 발급 페이지의 [새 열쇠 쌍 만들기]로 새로 만들고 `LIC_PUB`를 바꾼다(그러면 예전 키는 모두 못 씀). 첫 공개 열쇠 번호: `BBCAD-K1`.
* **한계(정직하게):** 브라우저에서 도는 공개 코드라, 소스를 고쳐 검사를 빼는 것까지 기술적으로 막을 수는 없다. 대신 이 장치는 저작권법상 **기술적 보호조치**이므로, 이를 일부러 피하거나 없애는 행위는 그 자체로 법 위반(저작권법 제104조의2)이 된다. 저장소가 공개라 소스는 누구나 볼 수 있으니, 더 강하게 지키려면 저장소를 비공개로 바꾸고(깃허브 페이지는 유료 요금제 필요) 상업용은 9절대로 분리한다.

## 14. 외부 조사 자료·SPICE 모델 반영 기준 (2026-11-26 추가)

사용자가 부품 조사 문서(데이터시트·유통사·포럼·위키를 인용한 보고서 + SPICE 코드)를 주고 반영을 요청했을 때 정한 기준입니다. 앞으로 비슷한 자료도 같은 기준으로 다룹니다.

* **사실과 표현을 나눈다.** 부품의 치수(핀 간격 2.54mm, 줄 간격 7.62mm, 다리 굵기), 정격(역전압·전류·제너 전압), 대표 특성(이 전류에서 순방향 전압 몇 V) 같은 **사실·수치는 저작권 보호 대상이 아니므로**(저작권법 제2조 제1호, 사상·감정의 '표현'만 보호) 쓸 수 있다. 하지만 조사 문서의 문장·표 구성·설명 순서는 그 작성자의 표현이므로 옮기지 않고, 필요한 사실만 골라 우리 말로 새로 쓴다. 조사 문서 원문은 저장소에 넣지 않는다.
* **남의 SPICE 모델을 옮기지 않는다.** 시뮬레이터에 딸린 표준 모델 파일, 반도체 회사가 배포하는 모델, 공개 모델 모음집의 값에는 각자 사용 조건(재배포 금지·고지 의무 등)이 붙어 있을 수 있다. 그래서 그 파일들의 파라미터 줄·서브서킷을 그대로 쓰지 않고,
  * 다이오드: 대표 특성점 세 개만 입력으로 `tools/fit-diode.py`가 IS·N·RS를 새로 계산한다(입력 특성점은 스크립트에 적어 둠). CJO·TT·BV·IBV는 정격·일반 특성에서 어림한다.
  * 릴레이·SSR·솔레노이드: 교과서 구성(코일 R-L, 지연 RC, 히스테리시스 스위치)을 앱의 시뮬레이터 기준(정격² ÷ 전력, 75%·10%)에 맞춰 새로 짠다. 지연·인덕턴스는 대표값 어림이라고 적는다.
  * 인덕터: CP = 1 ÷ ((2π·SRF)²·L), RP = Q·2π·f·L 같은 공식(누구나 쓰는 물리 식)으로 값을 만든다.
* **회사 전용 상품명·상표를 이름으로 쓰지 않는다(2절).** 여러 회사가 같은 규격으로 만드는 표준 등록 번호(1N4148, 1N4007, 1N5819, 1N4733A, 1N34A)는 부품 급을 알리는 기술 표기로만 쓰고, 한 회사만 쓰는 상품 번호·브랜드(특정 회사의 릴레이·SSR·인덕터 형번 등)는 앱·라이브러리·설명에 넣지 않는다. 대신 "DIP 8핀 DPDT 신호 릴레이", "레이디얼 드럼 코어 인덕터"처럼 종류 이름을 쓰고, 모델 이름은 `BB_` 로 시작하는 일반 이름으로 짓는다. 비호환 사례도 특정 상품을 지목하지 않고 "상자형 5V 파워 릴레이 중 핀이 격자에 맞지 않는 것"처럼 일반적으로 쓴다.
* **포럼·유통사의 측정 수치·문장을 그대로 인용하지 않는다.** 브레드보드 접점 저항·전류 한계처럼 널리 알려진 내용은 "접점마다 수십 mΩ, 연속 1A 안쪽" 정도의 일반 지식으로 우리 말로 쓴다.
* **검증은 우리 시험으로.** 라이브러리 값이 맞는지는 남의 자료와 대조한 문장이 아니라, 직접 만든 시험 회로(`spice/tb-*.cir`)를 ngspice로 돌려 확인한다(`node breadboard/tests/spice-check.js`). 앱 쪽 다이오드는 `tests/verify-parts.js`가 대표 범위 안에 드는지 본다.
* **면책.** 값은 대표값 어림이며 특정 회사 제품의 공식 모델이 아니라는 점을 라이브러리 머리말·`spice/README.md`에 적는다. 정밀 설계에는 실제 부품 제조사가 공개한 자료를 따로 확인하라고 안내한다.
* **같은 문서를 파일(.md)로 다시 받았을 때(2026-11-26):** 원문 파일은 저장소에 넣지 않고, 안내서 `PARTS-GUIDE.md`(앱 [부품 고르기] 창의 「브레드보드 부품 고르기 안내」)를 처음부터 새로 썼다. 글의 짜임(조건 → 다이오드 → 릴레이 → 코일 → SPICE 맞추기 → 점검표)·문장·표·예시 숫자(P = I²R 예: 0.1Ω에서 1A·5A)는 직접 만든 것이고, 원문의 회사 전용 형번 표(특정 회사 릴레이·포토MOS·인덕터 제품별 제원과 SPICE 값)는 "무리별 대표값 범위"로 바꿔 특정 제품을 가리키지 않게 했다. 휠러 근사식·공진 공식은 누구나 쓰는 물리 식이라 그대로 쓴다. 표준 등록 번호 UF4007·BAT85(여러 회사가 만드는 번호)는 부품 급 표기로만 쓰고, 그 SPICE 값도 `fit-diode.py`로 새로 계산했다.
* **결과물:** 앱 다이오드 6종(`d4148`·`d4007`·`d5819`·`dz51`·`dge`·`brdg`), `spice/bbcad-parts.lib`(저작자 서명 포함)·`spice/README.md`·시험 회로 3개, `tools/fit-diode.py`. 조사 문서에 있던 회사 전용 형번 모델(특정 회사 신호 릴레이·리드 릴레이·포토MOS 릴레이·인덕터 형번별 모델)은 만들지 않았다.
